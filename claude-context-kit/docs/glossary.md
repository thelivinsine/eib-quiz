# Glossary

Words this project uses in a particular way. Most of them are ordinary English doing technical work,
which is what makes them worth writing down — where a word below also has an everyday meaning, the
one given here is the one meant.

Ordinary terms a reader is assumed to know are **not** listed. That is the rule that keeps this file
short enough to read: a glossary that defines `JSON` is a glossary nobody finishes.

> **This file arrives empty on purpose.** It is a habit, not content. Add a word the first time a
> document has to explain it twice. The tables below are the shape that worked; the groups are
> whatever this project's vocabulary turns out to need.

## The record

Four that travel with the process rules, and are already true here:

| Word | Means |
|---|---|
| **a plan** | A document in [`plans/`](plans/) written *before* a body of work. **Never deleted** — it is the only record of what the work was expected to be, and the parts it got wrong are the valuable parts. |
| **shipped** | A plan whose work is merged. Marked, left in place, never removed. |
| **reversed** | A decision a later one overturned. It leaves a short note naming what replaced it, and its argument moves to [`archive/decisions.md`](archive/decisions.md). |
| **not verified** | A claim the tree alone cannot settle — a browser measurement, anything needing a build or a running app. **The half of a write-up that gets read before merging.** |
| **a sweep** | Checking *every* markdown file against the current state of the tree, not only the ones a session touched. |
| **minor / substantial / a diff review** | The three sizes a session can be, which decide whether its work is merged in place, stopped at a pull request, or merges an existing one. |
